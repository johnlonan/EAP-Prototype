## 0. Design Philosophy — Always Apply

Design with the combined thinking of **Jony Ive and Dieter Rams** — not as visual imitation, but as a way of reasoning about every decision.

**The standard:** The interface should feel inevitable. Calm. Quietly intelligent. So coherent it appears un-designed.

### The 10 Tests — Run These on Every Element
1. Can this be simpler without losing meaning?
2. Does this improve clarity, or just add presence?
3. Would removing it make the experience stronger?
4. Is it communicating structure, or just adding decoration?
5. Does the interface disappear and let the content take focus?
6. Is whitespace doing structural work, or is it just empty space?
7. Does motion feel purposeful and physically believable, or decorative?
8. Is the primary action unmistakably clear?
9. Does this addition improve the whole, or just the isolated section?
10. Would a senior industrial designer call this disciplined, or clever?

### Principles
- **Simplicity through depth** — achieved by thinking harder, not removing arbitrarily
- **Typography carries hierarchy** — weight, size, and colour do the structural work
- **Whitespace is architecture** — use it to separate, group, and breathe
- **Motion must be earned** — 150–300ms, ease-out enter, ease-in exit, no animation without meaning
- **System thinking over screen thinking** — every component, state, and transition must relate to the whole
- **Precision over decoration** — mathematical alignment, consistent rhythm, no visual gimmicks
- **Design for confidence and calm** — not stimulation

### What to Avoid
- Glassmorphism overload — the identity uses glass purposefully; don't pile it on
- Decorative gradients, floating clutter, or trend-driven UI
- "Minimalism theater" — removing things to look minimal without improving comprehension
- Components that work in isolation but break the system's coherence

**The final result must feel:** restrained, precise, human, timeless, effortless, technically refined, emotionally calm.

## 1. How You Work — Always Apply

### Think Before Coding
- State assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them — don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.

### Simplicity First
- No features beyond what was asked. No abstractions for single-use code.
- If you write 200 lines and it could be 50, rewrite it.
- No error handling for impossible scenarios.

### Surgical Changes
- Don't improve adjacent code, comments, or formatting unless asked.
- Match existing style, even if you'd do it differently.
- Every changed line should trace directly to the user's request.
- Remove imports/variables/functions that YOUR changes made unused.
- If you notice unrelated dead code, mention it — don't delete it.

### Design Discussions
- Discuss design direction BEFORE executing. Present options with research backing.
- When the user says "proceed" or "ok" — full autonomy, no further approval needed.
- When the user asks a question or challenges — stop, think, respond. Don't code.
- Reference NN Group, Gestalt principles, or Tufte when justifying visual decisions.

### Long Session Discipline
- In conversations exceeding 50 exchanges, re-read the most recent 5 user messages before any change.
- Do not rely on assumptions from early in the conversation — they may have been superseded.
- Commit to git before any risky change so "revert" is always available.

## 3. AINPX Design System — Always Evaluate

Apply these to every design decision. Not all will be relevant — evaluate, don't blindly apply.

### Core Principle
AINPX is intent-first, not navigation-first. The system learns the user, surfaces the right action at the right moment.

### Glassmorphism — The Visual Identity (Non-Negotiable)
- Body: gradient background (cool teal for standard, warm green for EA)
- Glass slab viewport: `rgba(255,255,255,0.48–0.68)` + `backdrop-filter: blur(24px)`
- Inner panels: `rgba(255,255,255,0.52)` + `blur(14px)`, 16–18px radius
- Layered shadows: outer soft falloff + inset edge highlights

### Design Tokens
```css
--color-primary: #0e4e69
--bg-page: #E5EDF0  --bg-primary: #fff  --bg-secondary: #F3F8F9
/* Text */   Primary: #111827  Secondary: #374151  Tertiary: #6B7280
/* Status */ Success: #16A34A  Warning: #D97706  Error: #DC2626
/* AI */     --ai-accent: #00C7B1  --ai-bg: #F0FAFA  (AI content ONLY)
```

### Typography
- 10px: labels, metadata, column headers (uppercase, 500 weight)
- 11px: secondary data values
- 12px: body text, table cells, pills
- 13px: titles, PI names
- Weights: 400 regular, 500 medium (signpost only — one per row), 600 semibold. Avoid 700 except primary metrics.
- `font-variant-numeric: tabular-nums` on all number columns

### AI Signal Rules
- The ✦ sparkle is the universal signal for AI-generated content
- Teal tokens reserved exclusively for AI — never for rule-based signals
- AI-inferred signals → show confidence score. Rule-based → never show confidence.

## 4. Data Visualisation Standard — Always Apply for Charts

Apply these automatically whenever adding a chart, card, or data visualisation.

### Tooling
- **D3.js** for complex charts requiring fine-grained control: stacked areas, CFD, burndown, scatter, bisect-hover, custom annotations, transitions.
- **Chart.js** (bundled — never CDN) for standard charts where speed matters: bar, line, doughnut, radar.
- Invoke the **d3-viz skill** before writing any D3 panel chart.
- No custom canvas drawing from scratch for anything beyond simple inline mini-charts.

### Hover Interactions — Mandatory on Every Chart, No Exceptions
- **D3 charts:** transparent overlay rect + bisect pattern. On mousemove: vertical crosshair, highlight nearest point, tooltip via `showTip()`. On mouseleave: clear both.
- **Chart.js charts:** configure the tooltip plugin. Callbacks must return secondary insight, not just the raw value.
- **Inline SVG mini-charts:** `data-hover="..."` on every interactive element. Wire `mouseenter` / `mousemove` / `mouseleave` post-render.
- Tooltips reveal secondary insight: `"In Progress: 14 items — WIP limit exceeded by 8"` beats `"In Progress: 14"`.
- Hover must feel immediate: no delay, crosshair cursor on chart area.

### Analytical Purpose First
- What is the user supposed to understand in under 3 seconds?
- What is the single key takeaway? Make it visually dominant.
- Does this chart earn its place, or does a number/text communicate it better?

### Chart Type & Data Shape
- Never map a narrow value range (e.g. 62–80%) onto a 0–100% scale — zoom to the relevant range or use a node/typographic layout.
- Equal-thirds node positioning for three-value comparisons — guarantees no label overlap regardless of input values.
- Horizontal bars beat vertical bars when one value dominates — equal row height prevents minority bars becoming invisible slivers.

### Label & Typography Rules
- Primary insight: largest, boldest, most coloured.
- Supporting values: smaller and muted. They confirm; they don't compete.
- Label only what's necessary: first + last on a sparkline, not every point.
- Check label overlap mathematically before committing: if two centered labels are within `(font-size × char-count)` pixels, they will collide. Redesign the layout.

### Range & Uncertainty
- Never use ± to express a probability range — it implies symmetric uncertainty. Use actual bounds: `"62–80% range, median 71%"`.
- Show ranges as multi-zone fills (solid floor / probable / upside). Dashed rectangles over solid fills are invisible.

### Data Coherence
- All demo values across cards must form one believable operational reality.
- Metrics, trends, owners, dates, and percentages must agree with each other and with any AI signal cards that reference them.

## 5. Pattern Reference — Load When Task Matches

### USE WHEN: Building AI-assisted views (chat, insights, recommendations)
- Module anatomy: Header → optional insight-before → Body → optional insight-after
- Human in the loop always: AI recommends, human approves
- Explainability is a feature — every AI ranking includes plain-language rationale
- Surface only what requires a decision — signal, not noise

### USE WHEN: Building card-based dashboards (home pages, briefings)
- Card system: white, 16–24px radius, 20–24px padding, subtle shadow
- Stat cards: large number (32px bold), label below (12px grey), trend arrow
- Needs-attention bands: Urgent (red border), AI Recommendations (amber), Strategy (teal)

### USE WHEN: Building conversation/chat views
- Split-screen: ~460px chat panel left, content right, resize handle
- User bubbles: right-aligned (teal bg), AI bubbles: left (no bg)
- Agent avatar: dark circle with sparkle. Chat bar docked at bottom.

### USE WHEN: Building tables and list views
- Minimal row borders: `1px solid rgba(0,0,0,0.04)`
- Headers: 10px uppercase grey, sticky with blur
- Status pills inline, avatar pills for people
- Link text for clickable names (primary colour, underline on hover)
- Pagination when > 20 rows

### USE WHEN: Building navigation and chrome
- Session-tab based, NOT breadcrumb-based
- Pill-style tabs: dark filled active, ghost inactive
- 64px icon nav from nav.js: outline default, filled active (separate SVG per state)
- Omnibar: centred, pill shape, rotating placeholder
