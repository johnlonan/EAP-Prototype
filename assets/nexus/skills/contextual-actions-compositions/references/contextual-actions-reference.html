Icon-only buttons MUST have aria-label — without it, screen readers announce nothing. The "More" overflow button gets both aria-label="More options" and aria-haspopup="true".

3. Quick Links — Grid Layout

Position: inside a card · Navigation shortcuts as icon + label tiles · ✅ Correct

Quick links

How to file expenses

Calendar
Documents

role="toolbar" aria-label="Quick links" grid layout — adapts columns to content each item is a link (navigational) icon bg: background-primary (same as card) + border-base-300 label: text-base-content, 11px icon radius: rounded-lg (8px)

Quick links are navigational contextual actions — each takes the user somewhere. Unlike button-based contextual actions, these use anchor tags (<a href>). The icon container uses background-primary (same surface as the card) with a border-base-300 border — the border provides the visual distinction, not a different background color. Note: the Figma spec may reference primary-content for this background — that's a spec error. primary-content is a text color (white), not a surface token. It doesn't change in dark mode.

4. Quick Links — List Layout

Position: inside a card · Vertical list of icon + label rows · ✅ Correct

Quick links

Expense reports and filing

same tile concept as grid — stacked vertically items are links (<a href>), not <li> icon: 36px container, background-primary + border-base-300, rounded-lg divider between each item interactive: hover + active states on rows disabled: opacity-40 + pointer-events: none

List layout is the same tile pattern as grid but stacked vertically — icon left, label right, dividers between rows. It is NOT a semantic <ul>/<li> list. Each item is a standalone navigation link, same as the grid tiles. Use list layout when labels are longer or when the card is narrow. Grid layout works for short labels and wider cards.

5. Filter Controls

Position: above a list · Pill-shaped chips · Mutually exclusive active state · ✅ Correct

Today's priorities

Review and take action to ensure smooth operations of AI in your org

Task High risk

Complete PII sensitive data assessment

Document data mining · Miley Simmons

Task High risk

Approve risk assessment completion

Document data mining · Miley Simmons

role="toolbar" aria-label="Priority filter" pill shape: rounded-full, border, px-4 py-2 active: filled dark bg + white text via aria-pressed="true" inactive: outlined, border-base-300 interactive: hover + active states on all pills NOT tabs — filters the same list, doesn't switch panels

Filter vs. Tabs distinction: If clicking changes which dataset is shown (completely different content), use the Tabs ARIA pattern (role="tablist"). If clicking filters the same dataset (narrowing visible items), use toggle buttons with aria-pressed. The visual treatment may look similar — the ARIA pattern is what differs. Filter pills are NOT DaisyUI btn classes — they are custom pill-shaped chips with filled/outlined states.

6. Common Violations

Each shows incorrect state with the rule it breaks.

❌ Mixed button variants in peer group

✗ Three different variants (ghost, outline, primary) If one button is btn-primary, it's the forward action — this is an action-set, not contextual actions. If they're all peers, use the same variant.
correct
✓ All btn-ghost — equal weight peers

❌ Hardcoded icon color instead of token

File Current (wrong) Correct
quick-actions-widget.js:217 style="color:#25CB40" text-primary class on 32px container + stroke="currentColor" (no bg)
quick-actions-widget.js:213 text-slate-700 text-tertiary (AI suggestions) or text-base-content
quick-actions-widget.js:238 rounded-3xl (24px — parent radius) rounded-xl (16px — nested radius)

Icon color uses text-primary class on the 32px container (no background), with SVG inheriting via currentColor. Text uses text-tertiary for AI suggestions. Overflow menu is a nested element — uses nested radius, not parent radius.

❌ Card header icon buttons without aria-label

✗ Icon-only buttons have no aria-label ✗ No role="toolbar" on container ✗ SVGs missing aria-hidden="true" Screen readers announce nothing for these buttons. Each needs aria-label describing the action ("Filter data", "More options").
correct
✓ aria-label on each button ✓ role="toolbar" on container ✓ aria-hidden on SVGs

❌ Filter pills without active state indicator

✗ No aria-pressed on any pill ✗ Active state is only visual — screen readers can't distinguish The filled pill looks active visually, but without aria-pressed="true", screen readers announce all three identically. Both the visual toggle and the ARIA state are required.
correct
✓ aria-pressed drives both visual state and screen reader announcement
