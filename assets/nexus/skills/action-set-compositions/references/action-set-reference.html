4. Common Violations

Each violation shows the incorrect state with the specific rule it breaks.

❌ Wrong color for approval context

✗ btn-primary on approval Approval context requires btn-success (green) — brand primary (teal) signals general action, not completion.
correct
✓ btn-success on approval

❌ Destructive adjacent to primary cluster

✗ No spacer before destructive Delete is adjacent to Cancel — accidental click risk. Destructive must be visually separated.
correct
✓ Spacer separates destructive

❌ Two forward action buttons

✗ Two btn-primary Only one forward action per action set. Demote the less committal action to secondary.
correct
✓ Save demoted to secondary

❌ More than 4 visible buttons

✗ 5 buttons visible (max 4) Secondaries overflow into dropdown. Forward action and destructive always stay visible.
correct
✓ Export + Duplicate in overflow menu overflow trigger = btn btn-outline + ellipsis icon

❌ Ghost button creates visual gap in group

✗ btn-ghost on Cancel — no visible container Ghost removes the border, creating a visual hole next to filled buttons. Dismissive actions use btn-soft (subtle fill). Secondary actions use btn-outline (border).
correct
✓ btn-soft — subtle fill, visible container

❌ Rejection without error treatment

✗ btn-outline on Reject — looks like a secondary action Rejection is a consequential negative decision — it needs btn-error (filled red) to signal its weight. Outline makes it indistinguishable from secondary actions like Reassign.
correct
✓ btn-error — rejection is consequential
