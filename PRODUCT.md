# Product

## Register

product

## Users

Enterprise agile planning practitioners at large financial institutions. Primary personas: Ananya (ART Product Manager), James (Senior Developer), Riya (Release Train Engineer), Dev (Scrum Master), Priya (Portfolio Director). They use this inside sprint planning sessions, PI ceremonies, and daily standups. Context is high-pressure, time-constrained, and data-dense. They are not casual users — they are experts who need the interface to disappear and the signal to dominate.

## Product Purpose

ServiceNow AINPX EAP (Enterprise Agile Planning) — a high-fidelity HTML/CSS prototype demonstrating the next-generation agile planning experience inside the ServiceNow platform. The Sand visual theme applies ServiceNow's production design language. Success means an evaluator can use the prototype and believe it is the real product, not a mockup.

## Brand Personality

Restrained. Precise. Quietly intelligent.

## Anti-references

- Glassmorphism as decoration (blur, rgba panels, light refractions)
- Gradient backgrounds and liquid effects
- Hero-metric template (big number, small label, gradient accent)
- "Minimalism theater" — removing things to look minimal without improving comprehension
- Generative AI aesthetic (floating cards, organic blobs, neon accents)
- Enterprise dashboard clichés (identical stat grids, icon + number + trend arrow arrays)
- Arrow characters on buttons or links

## Design Principles

1. **Whitespace is architecture.** Not empty space — structural space. Every gap separates, groups, or breathes.
2. **Typography carries hierarchy.** Weight, size, and colour do the structural work. One medium-weight signpost per row. Never 700 weight except primary metrics.
3. **Signal before chrome.** The content — the decision, the risk, the number — is the foreground. The interface is the background.
4. **Every element earns its place.** Apply the Rams test: would removing this make the experience stronger? If not certain it wouldn't, remove it.
5. **System coherence over screen completeness.** Every component, state, and transition must relate to the whole. A screen that looks good in isolation but breaks the system is a failure.

## Accessibility & Inclusion

WCAG AA minimum. ServiceNow Sans at all sizes — never fall back to system fonts. Tabular numerics on all data columns. Sufficient contrast on all text and status signals.
